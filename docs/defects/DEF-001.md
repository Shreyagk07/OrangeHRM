# DEF-001 — Leave Reset retains unmatched Employee Name text

**Status:** Open; prepared for Jira import, not logged in Jira. **Severity:** Low. **Priority:** P3. **Application:** official OrangeHRM Starter 5.7 release; no application source modifications. **Requirement/tests:** REQ-06, TC-040, UI-040.

## Environment and prerequisites

Local PHP 8.3.14 / Apache application, MySQL 8.4.3, Selenium Grid 4.27.0-20241204 on Docker Engine 28.5.1 / WSL2, Windows 11 host. Independently observed in Chrome 131.0.6778.108 and Firefox 133.0. A synthetic administrator is authenticated; no matching employee named SyntheticNoMatch is selected.

## Reproduction

1. Log in to the local application using the administrator configured in `.env`.
2. Open Leave → Leave List, or `/web/index.php/leave/viewLeaveList`.
3. Type `SyntheticNoMatch` into Employee Name without selecting an autocomplete result.
4. Click **Reset**.
5. Observe Employee Name after the reset and after the existing 20-second condition wait.

**Expected:** Reset clears the Employee Name filter input, as specified by REQ-06 / TC-040.

**Actual:** Employee Name still displays `SyntheticNoMatch`. The captured page shows other filter controls reset while this text remains. The business assertion reports the retained value explicitly. No employee or leave record mutation is involved.

This is separate from the fixed SMTP prerequisite and page-loading synchronization failures. The expected empty-value assertion remains active; it has not been skipped, changed to accept stale text, or retried automatically.

## Investigation and resolution

Root cause is **not established**. Source inspection shows [LeaveListTable.onReset](https://github.com/orangehrm/orangehrm/blob/v5.7/src/client/src/orangehrmLeavePlugin/components/LeaveListTable.vue) restores default filter models, while [EmployeeAutocomplete](https://github.com/orangehrm/orangehrm/blob/v5.7/src/client/src/core/components/inputs/EmployeeAutocomplete.vue) wraps the autocomplete control with `clear=false`. The relationship between selected model and raw query text is a candidate for investigation, not a confirmed root cause.

The local product remains the official release; no vendor patch or injected fault was applied. A prospective workaround is to clear the input manually or reload the page; this is not counted as a passing Reset test. No data corruption or authorization impact was demonstrated.
