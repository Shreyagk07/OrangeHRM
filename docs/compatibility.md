## Source-backed application contracts

Every link below is pinned to the selected tag; rendered OXD DOM classes remain subject to live-browser confirmation.

* [PIM routes](https://github.com/orangehrm/orangehrm/blob/v5.7/src/plugins/orangehrmPimPlugin/config/routes.yaml): `/pim/addEmployee`, `/pim/viewEmployeeList`, `/pim/viewPersonalDetails/empNumber/{empNumber}`; internal GET/POST/DELETE employee collection; GET employee; PUT personal-details.
* [EmployeeAPI](https://github.com/orangehrm/orangehrm/blob/v5.7/src/plugins/orangehrmPimPlugin/Api/EmployeeAPI.php): `employeeId`, `nameOrId` filters, JSON create payload, `ids` deletion array. **Generic employee PUT throws NotImplementedException**; the framework uses [EmployeePersonalDetailAPI](https://github.com/orangehrm/orangehrm/blob/v5.7/src/plugins/orangehrmPimPlugin/Api/EmployeePersonalDetailAPI.php) for updates.
* [Add Employee Vue](https://github.com/orangehrm/orangehrm/blob/v5.7/src/client/src/orangehrmPimPlugin/pages/employee/SaveEmployee.vue): first/last required; names max 30; employee ID optional max 10 and unique. [FullNameInput](https://github.com/orangehrm/orangehrm/blob/v5.7/src/client/src/orangehrmPimPlugin/components/FullNameInput.vue) explicitly sets `name=firstName/middleName/lastName`. Labels scope ID inputs. The actual rendered input-group, table and toast selectors are inferred from OXD components and must be browser-validated.
* [Personal Details](https://github.com/orangehrm/orangehrm/blob/v5.7/src/client/src/orangehrmPimPlugin/pages/employee/EmployeePersonalDetails.vue): UI ID max 10, despite the personal-details API's max 50 and schema varchar 50. Manual boundary cases use the **screen** constraint, not database capacity.
* [Employee entity](https://github.com/orangehrm/orangehrm/blob/v5.7/src/plugins/orangehrmPimPlugin/entity/Employee.php): table `hs_hr_employee`; key `emp_number`; fields `employee_id`, `emp_firstname`, `emp_middle_name`, `emp_lastname`. JDBC queries are SELECT-only and parameterized. Deletion is expected to remove the employee row through the application's deletion service; live validation pending.
* [Login Vue](https://github.com/orangehrm/orangehrm/blob/v5.7/src/client/src/orangehrmAuthenticationPlugin/pages/Login.vue), [ValidateController](https://github.com/orangehrm/orangehrm/blob/v5.7/src/plugins/orangehrmAuthenticationPlugin/Controller/ValidateController.php): form posts username/password plus `_token` to `/auth/validate`. Login page supplies a session-bound CSRF token. The browser performs this flow; REST Assured reuses authenticated cookies, never guesses Basic auth or a token URL. [AuthenticationSubscriber](https://github.com/orangehrm/orangehrm/blob/v5.7/src/plugins/orangehrmAuthenticationPlugin/Subscriber/AuthenticationSubscriber.php) produces JSON 401 for unauthenticated JSON requests. No separate API CSRF header was established in the inspected generic REST controller; cookies plus JSON headers reflect the client flow and need runtime confirmation.
* [System user form](https://github.com/orangehrm/orangehrm/blob/v5.7/src/client/src/orangehrmAdminPlugin/pages/systemUser/SaveSystemUser.vue): username required, 5–40 characters; role/employee/status required. [PasswordInput](https://github.com/orangehrm/orangehrm/blob/v5.7/src/client/src/core/components/inputs/PasswordInput.vue) uses a confirmation mismatch message even when confirmation is empty.
* [Leave list](https://github.com/orangehrm/orangehrm/blob/v5.7/src/client/src/orangehrmLeavePlugin/pages/LeaveList.vue) and [Apply](https://github.com/orangehrm/orangehrm/blob/v5.7/src/client/src/orangehrmLeavePlugin/pages/LeaveApply.vue): Leave module exists; date filters and employee reset are automated. Entitled leave creation requires additional configuration and is manual-only here.
* [Official noninteractive installer](https://github.com/orangehrm/orangehrm/blob/v5.7/installer/cli_install.php) and [its configuration](https://github.com/orangehrm/orangehrm/blob/v5.7/installer/cli_install_config.yaml): shipped but deprecated. The newer console explicitly refuses noninteractive mode. This explains the legacy CLI choice and migration risk.

PIM, Admin, Leave and Authentication are confirmed by source, along with other modules such as Time, Recruitment and Performance. Only the selected four enter this catalogue. Source presence proves implementation exists; it does not prove every module is enabled for every role in a deployed instance.

## Toolchain rationale

Live execution exposed a missing JSON serializer dependency: REST Assured does not supply one automatically. The project now pins [Gson 2.11.0](https://github.com/google/gson/releases/tag/gson-parent-2.11.0); [Gson's changelog](https://github.com/google/gson/blob/main/CHANGELOG.md) confirms Java record support from 2.10 onward. Real employee serialization and cleanup passed after this addition.

The fresh lab also needs email configuration for the reset form. [RequestPasswordController](https://github.com/orangehrm/orangehrm/blob/v5.7/src/plugins/orangehrmAuthenticationPlugin/Controller/RequestPasswordController.php) deliberately renders an email warning instead when configuration is absent. The environment now includes [Mailpit v1.21.8](https://github.com/axllent/mailpit/releases/tag/v1.21.8), using its [official Docker image](https://mailpit.axllent.org/docs/install/docker/): SMTP on internal port 1025 and a loopback-only viewer on 8025. The tagged [Dockerfile](https://github.com/axllent/mailpit/blob/v1.21.8/Dockerfile) supplies its `mailpit readyz` health check. `configure-mail.py` uses the verified [email configuration API](https://github.com/orangehrm/orangehrm/blob/v5.7/src/plugins/orangehrmAdminPlugin/Api/EmailConfigurationAPI.php), with SMTP auth/security `none`, and verifies saved values. It omits testEmailAddress and sends no test email.

[Cucumber TestNG parallel execution](https://cucumber.io/docs/guides/parallel-execution/) and [TestNG documentation](https://testng.org/documentation.html) define scenario DataProvider concurrency. Only `workers` controls that pool; suites do not add another parallel layer. One node slot per browser and two separate browser processes form the default benchmark matrix.

[Allure Cucumber documentation](https://allurereport.org/docs/cucumberjvm/) discusses avoiding duplicate TestNG/Cucumber entries. This project keeps the TestNG adapter in the API-only Maven profile; do not run UI with that profile. [Maven Wrapper](https://maven.apache.org/tools-archives/wrapper-3.3.2/) supplies the committed bootstrap scripts. All components are open-source; Jira Cloud is optional and not needed to execute tests.

## Observed runtime blockers

Initial PATH: Java and Maven missing; Python and Git available; Docker client 28.5.1 available. The JDK/Maven were subsequently downloaded to ignored workspace-local `.tools`. Docker Server was unavailable even after an outside-sandbox check (`dockerDesktopLinuxEngine` named pipe not found). WSL enumeration was denied in the sandbox. No application, database or browser integration has been claimed as executed. Exact build and dry-run outcomes belong in [validation](validation.md).

Firefox resource switches were verified in the actual pinned container: `/opt/bin/start-xvfb.sh`, `start-vnc.sh` and `start-novnc.sh` test `SE_START_XVFB`, `SE_START_VNC` and `SE_START_NO_VNC`; `/opt/bin/start-selenium-node.sh` tests `SE_ENABLE_TRACING`. The headless node now disables the unused display/VNC stack and unconfigured span export. This does not change application code or business assertions.
